# 独立双播台

面向 Windows x64 的独立桌面应用，不依赖运行中的 OBS，也不需要实体摄像头。两个 Tab 共用一个画面来源与裁剪布局：热播页输出 RTMP，百佳会页直接将 1080p、目标 60 fps 的节目画布送入“热播同窗口”虚拟摄像头，不创建独立共享窗口。摄像头从 OBS 32.0.4 开源 DirectShow 代码编译，具有自己的设备标识和画面通道，不再复用原 OBS 设备。首次安装需要管理员确认，不修改原 OBS 注册或场景设置。当前安装诊断和组件更新方式见 RELEASE-0.4.3.md；会议格式兼容修复见 RELEASE-0.4.2.md。

## 运行与打包

0.4.5 修复摄像头安装入口：无需实体摄像头或选择画面，已安装组件仍可重新注册修复，详见 `RELEASE-0.4.5.md`。0.4.4 新增顶部热播麦克风、系统与应用声音开关，以及 GitHub 在线更新。更新源已绑定 `DH-devmax/Go--`，用户无需设置仓库；发布与首次迁移见 `UPDATE-PUBLISHING.md`。

在 Windows 上安装 Node.js 与项目依赖后运行：

```sh
npm install
npm start
```

生成 Windows x64 目录包：

```sh
npm run package:win
```

目录位于 `release/Dualcast Independent-win32-x64`。打包会下载 Windows 版 FFmpeg 并校验其可执行文件格式；不再把 macOS FFmpeg 错装进 Windows 包。`npm run package:win:installer` 进一步生成支持应用内更新的 NSIS 安装器，位于 `release/updates`。macOS 开发机仍可用 `npm run package:mac` 打包测试，但目标平台是 Windows。

## 使用

1. 在任一 Tab 点击“选择共用画面”，选择 Firefox 或其他应用窗口并调整裁剪、位置。切换 Tab 仍显示同一预览，不必重复选择来源。
2. 百佳会页点击“安装独立摄像头”（无需实体摄像头，已有 OBS 组件也需要安装这个新设备）；已安装旧版独立组件时点击“更新摄像头组件”。完成后必须完全退出并重新打开会议客户端，以加载新 DLL。点击“启动虚拟摄像头”，在百佳会摄像头列表选择“热播同窗口”。原 OBS Virtual Camera 仍会保留。“验证摄像头”按设备默认格式回读本机独立设备画面，并显示快照实际分辨率。0.4.3 更新了驱动组件，旧版用户也需要点击更新。控制区刷新图标可检查注册、COM 激活和视频规格；安装阶段及检测结果会进入错误日志。
3. 两个输出共用画面配置，切换 Tab 不会停止 RTMP 或摄像头输出。更换来源会停止摄像头，需要重新启动；直播/录制中暂不允许更换画面。
4. 在热播或百佳会页的共用“共享混音器”中选择节目音频输入（例如节目专用虚拟线的录音端）和实体麦克风；“刷新设备”只枚举设备，设备名称未显示时点击“授权音频输入”，再点“启动混音”看两路电平。节目输入线路与会议回送线路必须是两条不同的虚拟线路。
5. 若会议需同时听到节目和麦克风，在“会议音频输出”中选虚拟线路的播放端，并在会议客户端将配对录音端选为**唯一麦克风**。若节目也使用虚拟线路输入，应另用一条线路，避免回采。摄像头不携带声音；会议客户端是否收到声音，需由参会者实听确认。
6. 热播页填写 RTMP 基础地址和完整推流码。先点“录制测试”检查本地文件，再确认“开始推流”。不会自行开播。
7. 热播页下方以独立受限视频视图载入指定观众端，只呈现网页中的 `<video>`，隐藏其它网页元素，按容器宽高等比适配。观众端在本机强制静音防回采，接收声音须用**另一台设备**确认。
8. 顶部“热播收音”可分别关闭热播麦克风与系统/应用声音，保持百佳会音轨。百佳会静音请到百佳会悬浮的 SDK 窗口操作。热播外部客户端与百佳会需分别使用不同虚拟输出；只有一条线路时留给百佳会，内置 RTMP 无需外部音频线路。

## 画面变换

- 采集后直接在预览中拖动画面移动位置，拖动红色边角等比缩放；按住 Shift 拖边角可拉伸。
- 按住 Alt（Mac 为 Option）拖边角裁剪，裁剪时边框为绿色。也可点亮“裁剪”按钮后拖边缘，不必按修饰键。
- 适配画布保留裁剪并居中放大；重置变换恢复完整画面；锁定后隐藏控制框并禁止拖动。方向键每次移动 1 个输出像素，Shift + 方向键移动 10 个像素。
- 两个 Tab 使用同一份采集来源、裁剪、位置、大小和锁定状态；切换来源或停止采集会重置。
- 节目画布为 1920×1080、目标 60 fps；摄像头直接使用该画布，RTMP/录制的最终编码保持原 720p/24 设置。原始画面的黑边可手动裁切。
- 变换即时进入本机预览、录制、热播和虚拟摄像头；控制框本身不会被输出。

## 边界与安全

- 虚拟摄像头模式使用节目画布，经 FFmpeg 转 NV12 后送至独立的“热播同窗口”。本设备只能有一个发送方；原 OBS Virtual Camera 使用另一个通道。状态区显示实际送帧率和源画面像素尺寸，目标 60 fps 不代表机器负载、源帧率和会议压缩后的接收结果均为 60 fps。Windows 会议端识别、清晰度、双客户端接收与性能尚需实测。
- 热播推流仅有一路，默认 1280×720、24 fps、H.264/AAC；不提供 OBS 场景、转场或多路推流。OBS 可以同时运行，但本应用不读取其场景。
- Windows 支持用户选择系统声音；此时会议回放等其他应用声音也可能进入采集。应用声音模式需要隔离的虚拟音频输入。观众端本机静音，节目输入与混音输出应避免互相回采。
- 会议音频使用 `setSinkId` 向用户选定的虚拟**输出**播放混音，再由会议端选择配对录音端；这不是系统级虚拟麦克风驱动。本应用不安装虚拟音频设备。设备是否支持、会议端是否收音及延迟/回声，都要在目标 Windows 机器上实测。
- 推流配置通过系统 `safeStorage` 加密保存在本机应用数据目录；若不可用，则不写入持久配置。不要把推流码提交到源码或日志，已暴露的推流码应在平台更换。
- 视频视图会连接用户给出的观众端页面，但不向其它站点跳转，也没有把观众网页嵌入主页面 DOM。目标站点的播放器实现变化时，纯视频模式可能需要更新。
- 未经用户点击确认，不向 RTMP 服务器发送画面。开发机测试不能替代 Windows 上的会议共享和平台收流端到端验证。
